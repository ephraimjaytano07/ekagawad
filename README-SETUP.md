# e-Kagawad — Now a Real PHP + MySQL System

This is your original front end (same HTML/CSS/JS look and feel — nothing
about the design was changed) now wired up to a real backend:

- **PHP** (`/api/*.php`) handles every action: login, registration, submitting
  requests, approvals, reports, notifications, account settings.
- **MySQL** (`database/schema.sql`) actually stores everything.
- **All the fake/dummy *transactional* data is gone.** There are no sample
  residents, no sample requests, and no sample notifications. The only
  exception, at your request, is one seeded admin account (`ADM-001` /
  `password`) so you can log in immediately — see step 4 below, and please
  change that password after your first login.
- **The six official document types are unchanged on purpose** (Barangay
  Clearance, Certificate of Residency, Certificate of Indigency, Certificate
  of Good Moral Character, Barangay Business Clearance, Barangay ID
  Application) — those are real, permanent system configuration, not sample
  data, so they were kept exactly as they were and are now seeded once into
  the `document_types` table.

## What's new / different under the hood

| Area | Before | Now |
|---|---|---|
| Data storage | JavaScript arrays in `js/data.js`, reset on every page refresh | Real MySQL tables, permanent |
| Passwords | A toy client-side hash | Real `password_hash()` / bcrypt on the server |
| File uploads | Stored as Base64 text in memory | Real files saved under `/uploads/requests`, path saved in DB |
| Login sessions | None (just a JS variable) | Real PHP sessions (`$_SESSION`), restored automatically on page refresh |
| Resident IDs / Request IDs | Hand-incremented counters in JS | Generated by the server from the real database |
| Barangay ID on registration | Not shown until after registering | **Shown live on the registration form** (auto-generated preview, based on the current number of residents), and confirmed again after signup |

## 1. Requirements

- PHP 8.0+ with the `pdo_mysql` extension enabled
- MySQL 5.7+ / MariaDB 10.3+
- Any web server (Apache/XAMPP/WAMP) — or just PHP's built-in server for testing

## 2. Import the database

Using phpMyAdmin, or the command line:

```bash
mysql -u root -p < database/schema.sql
```

This creates the `ekagawad` database, all tables, and seeds only:
- the 6 document types, and
- nothing else (no admin, no residents — see next step).

## 3. Configure the database connection

Edit `config/db.php` and set your real MySQL host/user/password if they're
different from the defaults (`localhost` / `root` / empty password, which is
the typical XAMPP/WAMP default).

## 4. Log in — an admin account is already seeded

`database/schema.sql` seeds one admin account so you can log in immediately,
using the same credentials as the original front-end prototype:

- **Admin/Staff ID:** `ADM-001`
- **Password:** `password`

**Change this password immediately** from the Admin Account page after your
first login — `password` is fine for local testing/school demo purposes but
is not a safe password to leave in place for anything real.

If you ever delete that seeded admin row and need a new first admin, open
**`setup_admin.php`** in your browser — it detects that no admin exists,
lets you create one with a properly generated password hash, then locks
itself (writes `setup_admin.lock`) so it can't be used to create a second
one by accident.

## 5. Make sure `/uploads` is writable

The `uploads/requests/` folder is where residents' supporting documents
(images/PDFs) actually get saved. Make sure your web server user can write
to it:

```bash
chmod -R 755 uploads
```

## 6. Run it

With PHP's built-in server (fine for testing/school demo):

```bash
php -S localhost:8000
```

Then open `http://localhost:8000` in your browser. For a real deployment,
put the whole folder on an Apache/Nginx server with PHP, pointed at
`index.html` as the entry point, with HTTPS enabled (passwords and session
cookies should always travel over HTTPS in production).

## 7. Replace the placeholder images

`assets/logo.png`, `assets/hall.jpg`, `assets/events.jpeg`, and
`assets/facilities.jpg` are currently simple placeholder graphics (since the
real barangay photos weren't available here). Just drop your real images in
with the same filenames — no code changes needed.

## How the six document types stay protected

`document_types` is real configuration data, not something residents or the
registration flow can add to or remove from. Only a developer editing
`database/schema.sql` (or a future "Manage Document Types" admin screen you
choose to build) changes what's offered. Nothing in this rewrite touches
their names, descriptions, requirements, or icons — they render exactly as
before.

## Security notes for a real deployment

- Always serve this over **HTTPS** in production — session cookies and
  passwords must not travel in plain text.
- Change the seeded/first admin's password immediately after first login
  (Account page), and don't reuse it.
- Consider adding rate-limiting / account lockout on repeated failed logins
  if this will be internet-facing.
- Back up the `ekagawad` database regularly — it now holds real resident
  and transaction data.
